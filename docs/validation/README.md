# Product validation — MicoPay Rentas

> **What this is:** short research tasks where contributors tell us, in their own words, whether they **understand** MicoPay Rentas, whether they **see value** in it, how the same problem looks **where they live**, what **confuses** them, and what **ideas** they have. MicoPay reviews every answer and writes the aggregate conclusions in [`SYNTHESIS.md`](./SYNTHESIS.md).

## How to take part

1. **Apply** to one of the `RT-V…` issues through the Drips bot. One assignee per issue.
2. Once assigned, **copy [`TEMPLATE.md`](./TEMPLATE.md) to `responses/<ISSUE-ID>.md`** (for example `responses/RT-V1.md`) and fill it in.
3. Open a **PR that only adds that file.** PRs that edit any other file are not merged.

You do **not** need to run the code. Reading the README is enough. Running the demo locally is optional; see the README for what it needs.

## The order matters

- **Step 1 is written first,** after reading only the README **up to its first `##` heading.** We want to know whether that opening explains the product on its own.
- Only then read the full README (and the code or the demo, if you want) and answer the rest.
- Do not edit step 1 after reading the rest. If you change your mind, say it in step 2; that is exactly what we want to learn.

## Privacy first

> ⚠️ No real names, phone numbers, addresses, wallet addresses, private keys, documents, receipts, transaction hashes or financial details. **We do not ask for any amounts of money** — not even ranges. A fee **percentage** is fine. Share only a **general country or region** and **your own** experience. Screenshots of the demo are fine (its data is fictional, on testnet). English or Spanish.

## First person only

Answer about **yourself**: what you understood, what you live or see where you live, what you would do. Do not survey other people, and do not write generalities ("people in X usually…") or text produced by a tool. It is fine to say "I don't know" or "this does not happen where I live".

## When a PR is accepted

- It follows the template and the privacy rules.
- Step 1 reads like a first impression, not a summary of the full README.
- Answers point at concrete parts of the product: a screen, a step of the flow, a sentence of the README.
- If not, we request changes.

## What we do with the answers

MicoPay reads every response and keeps an aggregate, anonymized synthesis in [`SYNTHESIS.md`](./SYNTHESIS.md): how many people understood the product from its opening, which misunderstandings repeat, the value rating, what people find most valuable or missing, how the problem looks in different regions, and the ideas that repeat. It never copies personal data.

This is a convenience sample of Drips contributors: a directional, qualitative signal, not a representative study.
